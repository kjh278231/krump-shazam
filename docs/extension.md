# 확장 프로그램 (Krump Track Finder)

작성 2026-10-19(README의 확장 프로그램 설명을 옮김). 전체 그림은 [개요](overview.md), 서버가 하는 검색은
[검색 파이프라인](search-pipeline.md)에 있다. 설치 방법은 [README](../README.md)의 "Running"에 있다. 영상별 기록(1.2.0)의
규칙과 API는 [영상별 기록](video-records.md)에 있다.

## 1. 파일

| 파일 | 역할 |
|---|---|
| `manifest.json` | Manifest V3. 권한 `tabCapture`, `offscreen`, `storage`, `activeTab`. 호스트 권한은 로컬 서버와 Lambda Function URL |
| `config.js` | 서버 주소와 API 키(`SERVER`). git에 없고 `python server/deploy/aws_setup.py function`이 쓴다 |
| `popup.html`, `popup.js`, `popup.css` | 툴바 팝업: 동의, 대기, 찾는 중, 결과 화면 |
| `background.js` | service worker. 팝업과 녹음기 사이를 잇고 상태를 `chrome.storage.session`에 둔다. 툴바 배지. 영상에서 끝난 찾기를 내 기록(`history`)에 남긴다 |
| `offscreen.html`, `offscreen.js` | 탭 오디오 녹음, 녹음 중 확인, 최종 검색. 영상 탭이면 요청에 영상 키(`vkey`)를 붙인다 |
| `video.js` | 탭 주소에서 영상 키(`videoKey`). 팝업이 쓴다 |
| `i18n.js`, `_locales/ko`, `_locales/en` | 화면 문장(1.3.0). 한국어 Chrome이면 한국어, 그 밖은 영어(§7) |
| `library.html`, `library.js`, `library.css` | 라이브러리 앨범 목록 탭 |
| `privacy.html` | 개인정보처리방침([같은 내용](privacy-policy.md)) |
| `icons/` | 툴바·스토어 아이콘 |

빌드 단계는 없다. 순수 JS·CSS를 그대로 불러온다.

화면이 바뀌면 `python store/shots/make.py check`로 모든 팝업 화면을 한국어·영어로 찍어 본다(§7).

**서버 연결.** 기본 서버는 배포된 AWS Lambda다([Lambda 배포](lambda-deployment.md)). 엔드포인트와 API 키는
`config.js`에 고정돼 있고, 확장 프로그램에는 이를 보거나 바꾸는 설정 화면이 없다. 로컬 서버(`server\start.bat`,
`http://127.0.0.1:8765`)를 쓰려면 이 파일을 고친다. 키는 확장 프로그램 파일과 요청 헤더에 그대로 들어 있어 숨겨지지
않는다.

## 2. 녹음 흐름

1. 팝업이 `chrome.tabCapture`로 스트림 id를 받아 녹음 길이와 함께 background service worker에 넘긴다. 길이는
   30초다. **못 찾음** 화면에서 다시 찾을 때만 45초나 1분을 고를 수 있고, 그 길이는 그 한 번에만 쓴다(§3).
2. background가 offscreen 문서를 띄운다. offscreen 문서는 `MediaRecorder`(Opus, 1초 조각)로 녹음하면서 소리를
   스피커로 계속 내보낸다. 첫 조각에 WebM 헤더가 있어 어느 시점까지 모은 조각이든 그대로 디코딩된다.
3. 10.5초부터 약 4초마다 지금까지의 녹음을 `POST /identify?partial=1`로 보낸다. 15초·20초 바로 앞에 걸리는 확인은
   15.5·20.5초로 미룬다(서버가 그 길이부터 기준을 낮추기 때문, [검색 파이프라인](search-pipeline.md) §4.7).
4. 서버가 `final`로 답하면(fingerprint 확정, 또는 길이에 비해 충분히 뚜렷한 rhythm 후보) 녹음을 바로 멈추고 그
   답을 결과로 쓴다. 아니면 최대 길이까지 녹음한 뒤 전체 녹음으로 최종 검색을 한다. 중간 확인은 끝나기 2초
   전까지 같은 간격으로 계속한다.
5. 녹음이 끝날 때 확인이 아직 돌고 있으면 그 답을 기다린다. 최종 검색을 같이 보내면 Lambda 인스턴스가 하나 더
   콜드 스타트로 뜨는데, 그쪽이 기다리는 것보다 느리다.
6. **지금 멈추고 검색**을 누르면 최소 길이(5초)를 채운 뒤 멈춘다.
7. **취소**(녹음 중과 마지막 검색 중)를 누르면 녹음을 멈추고 진행 중인 요청을 끊은 뒤 대기 화면으로 돌아간다.
   브라우저에는 결과도 내 기록도 남지 않는다. 서버가 이미 받은 요청은 끝까지 처리되므로, 취소 직전에 보낸 검색이
   확정되면 서버에는 녹음과 영상 기록이 남을 수 있다. background는 대기 상태에서 offscreen이 늦게 보낸 보고를 버린다.
8. 유튜브·인스타그램 영상 탭이면 팝업이 탭 주소에서 영상 키를 구해(`video.js` `videoKey`) 넘기고, offscreen 문서가
   요청마다 `vkey`로 붙인다. 동의한 경우(`share=1`)에만 보낸다. 서버는 최종 답에 `video`를 붙이고, 공유할 결과면
   영상별 기록으로 남긴다([영상별 기록](video-records.md)). 탭의 페이지(영상 재생 위치 등)는 읽지 않는다. 녹음 중
   스크립트로 영상 위치를 읽게 했더니 유튜브 재생이 0.1~0.4초씩 끊겨서 뺐다(2026-10-19 측정).
8. 답에 `video`가 있으면 background가 내 기록(`chrome.storage.local`의 `history`, 최근 100건)에 한 줄을 더한다.

팝업은 포커스를 잃으면 닫히지만 녹음은 계속된다. 상태(`state`)가 `chrome.storage.session`에 있어서 다시 열면
이어서 보인다. 툴바 배지는 REC(주황) → ...(회색) → OK(확정 주황, 확실하지 않음 노랑) / X(회색)이고, 오류는 ERR이다.

## 3. 팝업 화면

어두운 테마에 주황 강조색을 쓴다. 폰트는 Archivo(Google Fonts)와 한글용 Pretendard(jsDelivr,
`pretendardvariable-dynamic-subset`, v1.3.9 고정)이고, 오프라인이면 시스템 폰트(맑은 고딕)다. 예전 한글 폰트
IBM Plex Sans KR은 Windows 화면에서 버튼 글자가 살짝 깨져 보인다는 사용자 의견으로 바꿨다(2026-10-23). 라이브러리 페이지도
같은 폰트를 쓴다. 상태마다 화면이 하나다.

- **동의**: 처음 실행하면 개인정보처리방침 요약과 **동의하고 시작**만 보인다(§5).
- **대기**: 제목 "현재 탭에서 찾기", 버튼 **지금 나오는 트랙 찾기**와 "최대 30초 듣고, 곡이 확실해지면 바로 멈춰요 /
  팝업을 닫아도 계속 들어요" 안내. 녹음 길이는 고르지 않는다. 아래에 개인정보처리방침과 동의 철회 링크. 영상 탭에서는 아래
  "영상 탭의 대기 화면"이 더해진다. 제목(28px)이 버튼(17px)보다 너무 커 보인다는 의견으로 제목을 34px에서 줄이고 버튼 글자를
  15px에서 키웠다(2026-10-23, 다른 화면의 제목·버튼도 같이 바뀜).
- **찾는 중**: 제목 "찾는 중" 뒤의 점이 0.5초마다 하나, 둘, 셋으로 바뀐다. 최대 길이("최대 0:30", 다시 찾기에서 늘렸으면
  "최대 0:45", "최대 1:00"), 듣는 탭 제목, **지금 멈추고 검색**, **취소**. 녹음 중 힌트와 검색 세부는 보이지 않는다.

찾는 중 화면의 점 말고는 어느 화면에도 움직임이 없다. 애니메이션, 전환 효과, 경과 시간, 진행 막대를 모두 뺐다. 찾는 중 화면의
막대 그림도 멈춰 있고, 미리듣기도 재생 위치를 보여 주지 않는다. 이것들이 있을 때는 찾는 동안 캡처 중인 유튜브 탭이 자꾸
끊겼고, 빼고 나서는 끊기지 않았다(2026-10-22, 손으로 확인).

점은 찾는 중임이 보이게 해 달라는 사용자 의견으로 넣었다(2026-10-23). CSS 애니메이션이 아니라 0.5초 타이머가 점의
`visibility`만 바꾼다(`popup.js` `listening`). 레이아웃은 그대로이고 1초에 두 번 작은 영역만 다시 그린다. 예전 막대
애니메이션은 매 프레임 다시 그렸다. 점을 넣은 뒤 유튜브 탭이 끊기는지는 아직 손으로 확인하지 않았다. 끊기면 점도 멈춘다.
그 밖의 움직임은 넣지 않는다.
- **결과**: 찾음, 찾음 · 확실하지 않음, 못 찾음.
- **못 찾음**: 팁 세 줄, 최대 녹음 길이(30초 / 45초 / 1분, 처음엔 30초가 눌려 있음), **다시 찾기**. 다시 찾기는
  대기 화면을 거치지 않고 고른 길이로 바로 듣는다. 고른 길이는 저장하지 않아 다음 찾기는 다시 30초로 시작한다.
  예전 빌드가 `chrome.storage.local`에 남긴 `duration` 값도 읽지 않는다. 길이 선택은 이 화면에만 있다.

찾은 결과는 최고 곡 하나만 보인다.
- 앨범 커버, 트랙 이름, 앨범, 아티스트, 라이브러리 트랙 안의 위치("곡의 1:23부터").
- 서버가 확정하지 않은 결과(rhythm 후보, 낮은 점수, 가까운 라이벌)는 노란 배지와 "확실하지 않아요. 미리듣기로
  같은 곡인지 확인해 주세요." 안내가 붙는다. 미리듣기 플레이어는 확정과 같다.
- 앨범 판매 페이지 버튼: 밴드캠프 / KNKRTWORLD / Gumroad에서 앨범 구매. 아티스트 페이지만 찾은 앨범은 아티스트
  보기. 링크는 손으로 확인한 `db/album_links.json`에 있고([앨범 링크](album-links.md)), 앨범 319개 중 301개에 있다.
- 찾은 파일이 여러 앨범을 모은 폴더에 있으면, 같은 오디오의 사본(Panako id 또는 `db/same_audio.csv`)에서 앨범을
  가져온다.
- **10초 미리듣기**: 서버 `/preview`가 찾은 위치에서 자른 10초 MP3를 재생한다. 배포하면 저작권 문제가 있어서
  라이브러리 전체 파일은 내보내지 않는다. 요청에 API 키 헤더가 필요해서 `<audio src>` 대신 fetch로 받는다.
  최대 음량은 너무 커서 플레이어 음량을 절반(`volume = 0.5`)으로 둔다.
- **맞음 / 틀림**(결과가 맞나요?): 정답을 기록한다. 결과마다 한 번만 답할 수 있다. 답은 결과 id와 함께
  `chrome.storage.session`(`answered`)에 남아, 팝업을 다시 열면 버튼 대신 기록한 답이 보인다. 누르는 순간 저장하고,
  서버가 받지 못하면 지워서 다시 누를 수 있게 한다. 저장된 녹음(id가 있는 결과)에만 보인다.
- 머리의 **다시 찾기**는 대기 화면으로 돌아간다(다음 찾기는 30초). 영상 기록도 다시 조회해, 방금 찾은 곡이 목록에 보인다.

### 영상 탭의 대기 화면 (1.2.0)

팝업을 열 때 동의했고 녹음·검색 중이 아니면, 탭 주소의 영상 키(`video.js` `videoKey`)를 구해 `GET /video?key=`를 부른다
([영상별 기록](video-records.md) §5). 영상 탭에서는 이 요청이 `/health`를 대신해서(서버 점도 이 답으로 정함) 여는 순간의
요청 수는 예전과 같다. 3초 안에 답이 없으면 기다리지 않고 기록 없이 보인다. 녹음 중에는 조회하지 않는다. 중간 확인과
겹치면 콜드 인스턴스가 하나 더 뜰 수 있기 때문이다.

대기 화면의 맨 위(제목, **지금 나오는 트랙 찾기**)는 그대로이고, 그 아래에 **이 영상에서 찾은 곡**이 붙는다. 영상의 몇 초에 나오는
곡인지는 모르므로 지금 나오는 곡이라고 보이지 않는다.
- 다른 사용자가 찾은 곡이 하나면 결과 화면과 같은 카드(`songCard()`: 커버, 이름, 앨범, 곡 안 위치, 미리듣기, 판매 링크)로
  보인다. "다른 사용자가 이 영상에서 찾은 곡이에요." 또는 "…찾고 맞다고 확인한 곡이에요."가 붙고, 맞음 / 틀림은 없다(의심스러우면
  직접 찾기). 곡 안 위치와 미리듣기 시작점은 다른 사용자들이 찾은 위치의 중앙값이다.
- 둘 이상이면 곡 이름과 앨범·아티스트 줄의 목록이다(많이 찾은 곡부터).
- 공유 목록에 없는 내 기록(확인 없는 후보 "내 기록 · 확실하지 않음", "못 찾음", 영상당 최근 5개)이 목록에 이어진다.
- 마지막 결과·오류가 다른 영상의 것이면(탭의 영상 키가 상태의 `video.key`와 다르면) 대기 화면으로 돌아간다. 같은 영상이거나
  영상이 아닌 탭이면 예전처럼 마지막 결과가 남는다.

## 4. 라이브러리 페이지

팝업 머리의 **라이브러리**(점은 서버가 응답하는지 보여 줌)를 누르면 라이브러리 앨범을 커버 카드로 보여 주는 탭이
열린다.

- 카드마다 제목, 아티스트, 트랙 수, 판매처의 구매 / 아티스트 링크. **곡 목록**으로 앨범의 트랙을 펼친다.
- 앨범·아티스트·트랙 이름으로 검색하고, 전체 / 구매 가능 / 판매처 없음으로 거른다.
- 큰 커버는 판매처 이미지 CDN에서 불러오고(`art`, 밴드캠프 700 px), 안 되면 JSON에 들어 있는 120 px 썸네일, 그것도
  없으면 제목 타일을 보인다.
- 목록은 서버의 `/albums`에서 오고, 확장 프로그램에 캐시해서 다음에는 바로 보인다.

목록 다시 만들기(곡을 추가한 뒤):
- `python server/build_albums.py` → `db/albums.json` + `db/covers/`(`pip install mutagen pillow` 필요).
  - 앨범은 최상위 폴더 하나다. 이름은 파일의 album / album-artist 태그, 없으면 폴더 이름("Artist - Album")이다.
  - 여러 앨범의 트랙을 모은 폴더(`트랙리스트`)는 album 태그로 나눈다.
  - 커버는 파일에 들어 있는 그림(앨범 319개 중 287개)을 120 px JPEG로 만든다.
- 팝업은 판매처 커버를 먼저 쓴다: `python server/fetch_store_covers.py` → `db/store_covers/`(144 px, 앨범 226개).

## 5. 동의와 녹음 저장

- 확장 프로그램을 쓰려면 첫 화면에서 개인정보처리방침(`extension/privacy.html`, [개인정보처리방침](privacy-policy.md))에
  동의해야 한다. 대기 화면 아래 **동의 철회**로 거둘 수 있다.
- 동의는 방침 버전에 대한 것이다. `chrome.storage.local`의 `consent`에 동의한 방침의 시행일(`popup.js`의 `POLICY`,
  지금 `'2026-10-22'`)이 들어가고, 철회하면 `false`가 된다. 저장된 값이 `POLICY`와 다르면 동의 화면이 다시 뜬다.
  1.0.0은 `true`를 저장했으므로 1.2.0으로 올라가는 사용자는 모두 한 번 다시 동의한다. 1.1.0(시행일 2026-10-19 방침)은
  웹스토어에 내지 않고 1.2.0에 합쳤다(§6).
- 예전 방침에 동의했던 사용자(`true`나 다른 시행일)에게는 동의 화면에 "개인정보처리방침이 바뀌었어요." 아래
  `POLICY_CHANGE`(한두 줄)가 보인다. 지금은 1.0.0 사용자 기준으로 "녹음이 최대 1분으로 늘었어요." / "찾은 곡을 같은 영상을
  보는 다른 사용자에게 보여 줘요."다. 처음 쓰는 사용자와 철회한 사용자에게는 보이지 않는다.
- 방침을 고칠 때: `extension/privacy.html`과 [개인정보처리방침](privacy-policy.md)의 시행일과 9번(개정 이력)을 고치고,
  `POLICY`를 새 시행일로, `POLICY_CHANGE`를 바뀐 점 한두 줄로 바꾼다. 제출일이 바뀌면 패키징 직전에 이 셋의 날짜를 함께 고친다.
- 동의하면 확장 프로그램이 `share=1`과 함께 탭 제목·주소(영상 탭이면 영상 키도)를 보내고, 서버가 최종 녹음을 저장한다.
  `share`가 없으면(이전 빌드) 서버는 검색 뒤 오디오를 지우고 id를 돌려주지 않으며, 팝업은 맞음 / 틀림을 숨긴다.
- 1.2.0부터 동의 화면에 영상별 기록의 공유가 들어 있다. 영상 탭에서 팝업을 열면 영상 id를 보내 조회하고, 찾은 곡은 같은
  영상을 여는 다른 사용자에게 보인다(녹음, 탭 제목, 누가 찾았는지는 안 보임). 동의하기 전에는 조회하지 않는다.
- 동의를 철회하면 브라우저의 내 기록(`history`)도 지운다.
- 서버는 접근 로그를 남기지 않는다(요청 URL에 탭 제목이 들어 있기 때문).
- Lambda에서는 저장한 녹음이 S3에 간다(버킷의 `recordings/<id>.wav` + `<id>.json`).
- 로컬 서버에서는 `recordings/`에 남고 `recordings/log.csv`에 기록된다. 이 파일은 그대로 `evaluate.py` manifest로
  쓸 수 있다(피드백이 없는 줄은 건너뜀): `python poc/evaluate.py --manifest recordings/log.csv`.

## 7. 언어 (1.3.0)

작성 2026-10-26. 설계는 `docs/superpowers/specs/2026-10-26-english-support-design.md`.

- Chrome UI 언어가 한국어면 한국어, 그 밖의 모든 언어는 영어다. `_locales/ko`와 `_locales/en`만 두고 `default_locale`은
  `en`이다. 고르는 설정은 없다. Chrome UI는 영어인데 웹사이트 선호 언어만 한국어인 사람은 영어로 본다.
- 문장은 모두 `_locales/<언어>/messages.json`에 있다. 숫자가 끼면 메시지 안에 `$1`을 쓴다. 이름과 설명(`manifest.json`의
  `__MSG_ext_name__` 등)도 여기서 온다.
- `i18n.js`(각 페이지 스크립트보다 먼저 불러옴): `t(이름, ...값)`, 보이는 언어 `LANG`, HTML의 `data-i18n` 채우기
  (`localize`), 오류 문장(`errorText`), 앨범 이름 `'단일 곡'`의 영어 표기(`albumTitle`, 서버 데이터는 그대로).
- 오류는 문장이 아니라 `{ code, status?, detail? }`로 오간다. offscreen 문서에는 `chrome.i18n`이 없어서, 팝업이
  `errorText`로 문장을 고른다. 서버 오류는 응답의 `code`([검색 파이프라인](search-pipeline.md) §6)를 쓰고, 모르는 `code`나
  `code`가 없는 응답은 "서버 오류 N"이다. 서버의 한국어 `detail`은 보이지 않는다. 1.2.0이 남긴 문자열 오류는 그대로 보인다.
- 시험: `node --test "tests/*.test.mjs"`가 두 언어의 키와 `$n`이 같은지, 코드에서 쓰는 키가 모두 있는지, 코드 문자열에
  한국어가 남지 않았는지 본다.
- 화면 확인과 스토어 스크린샷: `store/shots/`. `stub.js`가 `chrome.*`와 서버를 흉내 내고, 실제 `popup.js`·`library.js`를
  headless Chrome으로 찍는다. `python store/shots/make.py check --key-file <키 파일>`은 모든 팝업 화면과 라이브러리 페이지를
  두 언어로 `build/shots/check/`에 찍는다. 라이브러리 앨범 목록은 실행 중인 로컬 서버의 `GET /albums`에서 커버를 빼고 가져온다.
  영어 문장이 길어 넘치면 먼저 문장을 줄인다.
